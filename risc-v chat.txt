//   IF (Fetch) -> ID (Decode) -> EX (Execute) -> MEM (Memory) -> WB (Writeback)
// Features:
//   - Data forwarding (EX/MEM and MEM/WB to EX stage)
//   - Basic pipeline control (no hazard stalling yet)
//   - RV32I Base Integer ISA support

    input  logic        clk,
    input  logic        rst_n,
    input  logic [31:0] instr_if,
    output logic [31:0] pc_if
);

    // Pipeline Registers
    // ------------------------------------------------------------

    logic [31:0] pc_id, instr_id;

    logic [31:0] pc_ex, rs1_data_ex, rs2_data_ex, imm_ex;
    logic [4:0]  rs1_ex, rs2_ex, rd_ex;
    logic [2:0]  funct3_ex;
    logic [6:0]  funct7_ex;

    logic [4:0]  rd_mem;
    logic        reg_write_mem, mem_write_mem, mem_to_reg_mem;

    logic [31:0] alu_result_wb;
    logic [4:0]  rd_wb;
    logic        reg_write_wb, mem_to_reg_wb;

    // ------------------------------------------------------------
    // Stage: IF (Instruction Fetch)
    // ------------------------------------------------------------
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            pc_if <= 32'h0;
        end else begin
            pc_if <= pc_if + 4;
        end
    end

    // IF/ID Pipeline Register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            pc_id <= 32'h0;
            instr_id <= 32'h0;
        end else begin
            pc_id <= pc_if;
            instr_id <= instr_if;

# Wrote docs\architecture.md
# RV32I Processor Architecture Documentation

## Overview

This document describes the architecture of the RV32I 5-stage pipelined RISC-V processor implemented in SystemVerilog. The processor implements the RV32I base integer instruction set with a classic 5-stage pipeline.

## Pipeline Stages

### 1. IF (Instruction Fetch)
- **Function**: Fetches instruction from instruction memory using PC
- **Registers**: Program Counter (PC)
- **Output**: 32-bit instruction, PC+4
- **Key Logic**: PC increments by 4 each cycle (no branch prediction yet)

### 2. ID (Instruction Decode / Register Fetch)
- **Function**: Decodes instruction, reads register file, generates immediates
- **Operations**:
  - Extracts opcode, funct3, funct7, rs1, rs2, rd fields
  - Reads register file (2 read ports, asynchronous)
  - Control unit decodes opcode to control signals
  - Immediate generator sign-extends immediates (I/S/B/U/J types)
- **Outputs**: Register values, immediate, control signals, register addresses

### 3. EX (Execute)
- **Function**: Performs ALU operations
- **Components**:
  - ALU Control: Maps (alu_op, funct3, funct7) → alu_control
  - ALU: 10 operations (ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU)
  - **Forwarding Unit**: Resolves RAW hazards by forwarding from EX/MEM and MEM/WB
- **Branch Logic**: Evaluates branch conditions (BEQ, BNE, BLT, BGE, BLTU, BGEU)

### 4. MEM (Memory Access)
- **Function**: Data memory access (load/store)
- **Current Status**: Pass-through for simulation (no actual memory)
- **Registers**: alu_result, rs2_data (store data), rd, control signals

### 5. WB (Write Back)
- **Function**: Writes result back to register file
- **Data Source**: ALU result (or memory data for loads)
- **Register File**: 1 write port, synchronous

## Data Forwarding

The processor implements full data forwarding to resolve Read-After-Write (RAW) hazards:

| Forward Path | Source Stage | Destination | Latency |
|--------------|-------------|-------------|---------|
| EX/MEM → EX | ALU Result | ALU Operand | 1 cycle |
| MEM/WB → EX | WB Result | ALU Operand | 2 cycles |

**Forwarding Logic** (in `rv32i.sv` EX stage):
```systemverilog
// Forward A (rs1)
if (reg_write_mem && (rd_mem != 0) && (rd_mem == rs1_ex))
    forward_a = 2'b10;  // From EX/MEM
else if (reg_write_wb && (rd_wb != 0) && (rd_wb == rs1_ex))
    forward_a = 2'b01;  // From MEM/WB
else
    forward_a = 2'b00;  // No forwarding
```

## Control Signals

| Signal | Description | Stages |
|--------|-------------|--------|
| `reg_write` | Enable register write | ID, EX, MEM, WB |
| `alu_src` | ALU operand B select (0=rs2, 1=imm) | ID, EX |
| `mem_write` | Enable data memory write | ID, EX, MEM |
| `mem_to_reg` | WB data select (0=ALU, 1=memory) | ID, EX, MEM, WB |
| `branch` | Branch instruction | ID, EX |
| `jump` | Jump instruction (JAL/JALR) | ID, EX |
| `alu_op` | ALU operation selector (2 bits) | ID, EX |

| Instruction | Opcode | Operation |
|-------------|--------|-----------|
| JAL | 0x6F | rd = PC+4; PC = PC + imm |

## Register File

- **32 registers** (x0-x31), each 32 bits
- **x0 hardwired to zero**: reads return 0, writes ignored
- **2 read ports** (asynchronous), **1 write port** (synchronous, posedge clk)
- **Reset**: All registers cleared to 0 on active-low reset

## Immediate Formats

| Type | Bits | Format |
|------|------|--------|
| I | 12 | `instr[31:20]` |
| S | 12 | `instr[31:25], instr[11:7]` |
| B | 13 | `instr[31], instr[7], instr[30:25], instr[11:8], 1'b0` |
| U | 20 | `instr[31:12], 12'b0` |
| J | 21 | `instr[31], instr[19:12], instr[20], instr[30:21], 1'b0` |

All immediates are **sign-extended** to 32 bits.

## ALU Operations

| alu_control | Operation | Description |
|-------------|-----------|-------------|

# RISC-V Processor Implementation

A fully functional **RV32I (32-bit RISC-V) 5-stage pipelined processor** implementation in SystemVerilog. This project implements the RV32I base integer instruction set with a complete pipeline of modular components, each accompanied by self-checking testbenches.

## Project Overview

This processor implements a **5-stage pipelined datapath** with the following key features:
- **RV32I Base Integer ISA**: Complete 32-bit RISC-V base integer instruction set
- **5-Stage Pipeline**: IF → ID → EX → MEM → WB with data forwarding
- **Modular Design**: Clean separation between datapath and control units
- **Self-Verifying**: Each module includes comprehensive self-checking testbenches
- **Simulator**: Icarus Verilog 11.0 (`iverilog -g2012` + `vvp`) in WSL Ubuntu 22.04

## Architecture

The processor follows a classic 5-stage RISC-V pipeline design:

```
PC → IF (Fetch) → ID (Decode) → EX (Execute) → MEM (Memory) → WB (Writeback)
                        ↓
                 Control Unit → ALU Control → Immediate Generator
```

### Pipeline Stages

| Stage | Function | Key Components |
|-------|----------|----------------|
| **IF** | Instruction Fetch | PC register, instruction memory interface |
| **ID** | Decode / Register Fetch | Register file, control unit, immediate generator |
| **EX** | Execute | ALU, ALU control, **data forwarding unit** |
| **MEM** | Memory Access | Pass-through (simulation) |
| **WB** | Write Back | Register file write port |

### Data Forwarding

The processor implements **full data forwarding** to resolve RAW hazards without stalling:
- **EX/MEM → EX**: Forward ALU result from previous instruction (1 cycle latency)
- **MEM/WB → EX**: Forward writeback result from 2 cycles ago (2 cycle latency)

## Key Design Decisions

### 1. 5-Stage Pipeline
Standard RISC pipeline with IF, ID, EX, MEM, WB stages for maximum clock frequency.

### 2. Modular Control
Separation between main control unit (`ctrl.sv`) and ALU control (`alu_ctrl.sv`) provides clean abstraction.

### 3. Combinational ALU & Forwarding
The ALU and forwarding muxes use `always_comb` for zero-latency operation.

### 4. Hardwired x0
Register x0 is hardwired to zero in the register file, following RISC-V specification.

### 5. Sign Extension
Immediates are correctly sign-extended using replication operators (`{{N{bit}}}`).

## Performance Characteristics

- **Pipeline Depth**: 5 stages
- **Register Ports**: 2 read (async), 1 write (sync)
- **ALU Latency**: 1 cycle (EX stage)
- **Forwarding**: 2 paths (EX/MEM, MEM/WB → EX)
- **Branch Resolution**: EX stage (2-cycle penalty on taken)

## Known Limitations

1. **No load-use stall**: LW followed by dependent instruction needs 1-cycle bubble
2. **No branch prediction**: PC always increments by 4; taken branches not yet implemented in PC
3. **No memory interface**: MEM stage is pass-through for simulation
4. **No exception/interrupt handling**
5. **No CSR/privilege support**
